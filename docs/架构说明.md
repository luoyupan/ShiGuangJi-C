# 架构说明

## 1. 为什么是「C 宿主 + WebView2 + dll 模块」

原版是 Electron：主进程 Node + Chromium 渲染进程 + preload 白名单。C 版保留三件事的**语义**：

| Electron 概念 | C 版对应 |
|---|---|
| BrowserWindow + Chromium | Win32 窗口 + WebView2（系统 Edge 内核） |
| `main.js` 的 `ipcMain.handle` | 宿主 HTTP `/api` + 模块 `invoke` |
| `preload.js` 的 `contextBridge` | 原样保留的 `preload.js` + 一个假的 `require('electron')` 桥 |
| 主进程主动 `webContents.send` | SSE `/events` |
| `src/main/{module}` Node 服务 | `modules/<module>.dll` 里的 C |
| `file://` 本地图/音频 | 宿主 `/local` 代理（支持 Range） |
| `sgj-mod://` 自定义协议 | 宿主 `/mod/<id>/renderer.js` |
| asar 打包 | 前端资源压成 `ui.zip` 编进 exe 的 `UI_ZIP` 资源 |

## 2. 进程 / 线程

```
主进程 ShiGuangJi.exe (C11, /MT)
├─ UI 线程（WinMain 消息循环）
│   ├─ 主窗口（WS_POPUP + WS_THICKFRAME，WM_GETMINMAXINFO 贴工作区）
│   ├─ WebView2 #1：应用界面
│   ├─ WebView2 #2：浏览器画布（子窗口 class SGJBrowserChild）
│   ├─ message-only 窗口 SGJBrowserMsg：把工作线程的 WebView2 调用 SendMessage 回 UI 线程
│   └─ 对话框（IFileOpenDialog）在工作线程 CoInitialize(STA) 后调
├─ HTTP accept 线程
│   └─ 每连接一个线程（recv 头/体 → 路由 → 响应）
├─ SSE 心跳线程（15s 注释帧）
├─ store 防抖线程（1.2s 检查脏标记）
├─ games 进程守护线程（每个运行中的游戏一条）
├─ netdisk 下载线程（每任务一条，WinHTTP 流式）
└─ link 监听/转发线程（TCP accept、UDP select、聊天 accept、中转 accept）
```

- **WebView2 的 COM 调用只能在创建它的 UI 线程**：浏览器画布的所有操作都通过
  `SendMessageW(g_msgwnd, WM_BV_*, ...)` 回 UI 线程执行，工作线程不直接碰 COM。
- 模块 `invoke` 由宿主全局锁串行化；模块内部的线程（下载/守护/转发）自己负责同步。
- `store` 有独立临界区，任何线程都能安全 `get/set/merge`；写盘防抖 + 原子替换。
- SSE 广播有每客户端锁 + 全局列表锁，发送失败即摘除。

## 3. IPC 协议

前端 `preload.js` 不改：

```js
const res = await ipcRenderer.invoke(channel, ...args);
if (res.ok) return res.data; else throw new Error(res.error);
```

桥接层（`ui/js/sgj-bridge.js`）：

```js
POST /api   { channel: "games:list", args: [ {...} ] }
         →  { ok: true, data: [...] }  |  { ok: false, error: "..." }
GET  /events  text/event-stream
         →  data: {"channel":"games:run-state","payload":{...}}
```

宿主分发顺序：

1. `api.c` 里的宿主频道（`app:*`、`settings:*`、`plugins:*`、`win:*`、`dialog:*`、
   `browser:view*`、`update:*`、`plugin:*`…）；
2. 没有命中 → `modules_dispatch()`：按清单 `channels` 的**最长前缀**找 dll，调用
   `invoke(channel, args_json, &out_json, &out_error)`；
3. 都没有 → `{ok:false, error:"C 版还没有实现这个接口：…"}`（界面 toast，不白屏）。

`/api` 返回的数据在桥接层还会做一次 **`file://` → `/local/` 深转换**，这样封面、
音频、缩略图在 WebView2 里都能直接加载（Chromium 默认不允许 http 页面读 `file://`）。

## 4. 内嵌 HTTP 服务

- 只绑 `127.0.0.1`，端口 `bind(0)` 随机；所有路径必须带 32 位随机 token：
  `http://127.0.0.1:<port>/t/<token>/…`
- 静态资源来自 `ui/`（开发态）或从 `UI_ZIP` 解到
  `%LOCALAPPDATA%\ShiGuangJi-C\ui-<版本>`（发布态）；
- `/local/<url-encoded path>` 支持 `Range: bytes=…`、`206 Partial Content`、
  `Accept-Ranges`；音频拖动进度、图片懒加载都靠它；
- `/mod/<id>/renderer.js|style.css` 从 dll 的资源块直接返回（不落盘）；
- `/events` 是 SSE；C 侧 `bus_emit_json()` 广播；
- 文件名里的 `#`、`?`、`%`、中文都由 `url_encode_path` 逐字节编码，避免原版踩过的
  「`#` 截断导致封面空白/音频 Format error」。

## 5. 模块加载

1. `modules_init(exe_dir\modules)`：`FindFirstFile *.dll`；
2. `LoadLibraryEx(..., LOAD_WITH_ALTERED_SEARCH_PATH)`；
3. `GetProcAddress("sgj_module_entry")`；校验 `abi == SGJ_ABI`；
4. `module.json` 必须能解析，且有 `id/route/title`；
5. `init(host_api)`；失败只记错误，不影响主界面；
6. 频道前缀进路由表（最长前缀优先）；
7. `modules:list` 给界面 `rendererUrl/styleUrl/hasStyles/native`；
8. 界面启动时 `shell.loadDllModules()` 动态 `<script src=/mod/id/renderer.js>`。

第三方 dll 的界面走 `SGJPlugin.define()`，宿主在 `#/p/<id>` 时懒加载；
内置 dll 的界面走原版路由（`#/games` 等），启动时加载。

## 6. 数据

- 路径：`%APPDATA%\shiguangji\shiguangji.json`（和原版相同，可直接互相读取）；
- 顶层命名空间：`settings/plugins/hidden/games/music/netdisk/link/photos/browser/profile`；
- 读：默认值 + 存档 **深合并**（存档优先）；数组整体替换；
- 写：`store_set/merge` → 脏标记 → 1.2s 防抖 → 临时文件 + `MoveFileEx` 原子替换；
- 「删除 / 清空」一律 `set`，不用 `merge`（避免旧元素被合并回来）；
- 各模块只写自己的命名空间，未知字段原样保留（`cJSON` 深拷贝）。
- 附属数据：`covers\`、`music-covers\`、`photo-index.json`、`photo-thumbs\`、
  `link-netinfo.enc`、`plugin-data`（第三方私有存储）。

## 7. 隐藏空间密码

原版：`crypto.scryptSync(password, salt, 64, {N:16384, r:8, p:1})`，
存 `salt`（16 字节 hex）+ `hash`（64 字节 hex）。

C 版：`games.dll` 里手写 scrypt：
- PBKDF2-HMAC-SHA256 走 Windows CNG `BCryptDeriveKeyPBKDF2`；
- Salsa20/8 + BlockMix + ROMix 按 RFC 7914；
- 参数/字段/长度和 Node 完全一致，**原版密码可直接解锁**；
- 已用真实 `salt/hash` 验证输出逐字节一致。

## 8. 构建

`build.ps1`：
1. 找 `vcvars64.bat`（VS 2022 Build Tools）；
2. 复制 `ui/` → `build/ui`，`tar -a -c` 成 `build/ui.zip`；
3. 生成 `gen/ui.rc`（`UI_ZIP RCDATA`）和 `gen/app.rc`（图标 + 版本信息）；
4. 编宿主：`src/host/*.c + cJSON.c`，链 `WebView2LoaderStatic.lib` 与系统库；
5. 每个模块：拼 `renderer.js` → 生成 `MANIFEST/UI_JS/UI_CSS` 资源 →
   `rc` + `cl /LD` → `build/modules/<id>.dll`；
6. 运行时 exe 若发现旁边没有 `ui/index.html`，就从 `UI_ZIP` 解压。

所有二进制 `/MT` 静态 CRT，发布只需 exe + `modules\*.dll`（+ 系统 WebView2）。
